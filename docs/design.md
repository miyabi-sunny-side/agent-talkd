# Remote session console

The service has no broker state. A request reads live Herdr destinations, validates an expected session, and either prompts that CLI or reads its native transcript. The CLI transcript is the only conversation store. Normal diagnostic logging remains on stderr; message bodies are not logged by the HTTP adapter.

`Herdr::list/get` combine Herdr's agent identity with foreground process information. The opaque `session_id` changes when native session metadata or the owning process changes. Display labels are not addresses. Every submission resolves the pane again and checks its identity and state before executing `herdr agent prompt <pane> <body>` with the original body as one argument. Per-process submissions are serialized to avoid interleaved terminal input. Herdr does not offer atomic compare-and-prompt, so a process replacement between the check and prompt cannot be fully excluded. A failed mutating acknowledgement is indeterminate and never retried automatically.

The HTTP API has four application operations: agents, conversation, screen, and messages. No peer API, MCP, broker RPC, message queue, mailbox allowlist, acknowledgement, or terminal-control API exists. The server listens on `0.0.0.0` using `PORT` (default `5002`); the Tailscale/proxy operator controls reachability. Origin and input validation do not distinguish a human from a same-privilege agent process.

Herdr CLI owns connection discovery and RPC. Each invocation has a five-second timeout, bounded stdout/stderr, and no shell or automatic retries. The prompt parser takes the body at its fixed position, including leading dashes; it does not accept a separate `--` delimiter. Structured commands return JSON on stdout; server errors use JSON on stderr with a nonzero exit code. Prompt failures without a definite rejection remain indeterminate.

Screen reads use `herdr pane read <pane> --source visible --format text`, bounded to 256 KiB. Herdr 0.8.2 emits plain text for this command, without pane identity or truncation metadata, so the adapter retains the explicit pane argument and identity checks around the read. The expected terminal is checked before and after reading; native identity is optional so unregistered or unsupported agents remain observable. This read-only snapshot is neither a pixel screenshot nor conversation storage. The browser keeps its successful capture time and identifies stale content after failure, departure, or replacement. Hidden screen views do not poll.

Transcript paths come from Herdr session metadata or a bounded search under the appropriate CLI history root. User input cannot select a filesystem path. Readers validate native identity, bound bytes/entries, ignore partial records at the live append boundary, and expose user/assistant text only. The basic response reports truncation so the interface never claims full-history completeness.

The native reader remains in place until Herdr can own history acquisition. Herdr 0.8.2 supplies native references but no conversation-page API. The [history ownership contract](history-ownership.md) records the required capability and deletion map. Delivery scope is unresolved. The transfer and removal of the app's HOME requirement are not implemented. Terminal snapshots must not replace conversation history during that transition.

The embedded Svelte app is built before Cargo. Releases for Linux and macOS contain one executable and LICENSE. No background worker or companion MCP binary is installed. Historical broker decisions in `docs/decisions` are superseded records, not current implementation requirements.
